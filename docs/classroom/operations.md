# クラス管理 運用手順書（復旧対応）

> **🆕 Smalruby 独自** — クラス管理の「消えた課題を復旧してほしい」問い合わせに対応する運用者向け手順。

対象読者: AWS クレデンシャル（SSO）を持つ運用者。仕組みの背景は [architecture.md](architecture.md) の「削除スナップショットと長期保持」を参照。

## 問い合わせ対応フロー

「クラス（課題）が消えた / 誤ってアーカイブしたので復旧してほしい」と連絡が来たら:

```text
1. まず「アーカイブか、期限切れか」を判別する
   ├─ 先生の UI で確認してもらう:
   │    クラス一覧 →「アーカイブ済みのクラス」/ 課題ボード →「アーカイブ済みの課題」
   │    → ここに見えていれば【誤アーカイブ】→ 先生自身が「元に戻す」で復元完了（運用者対応不要）
   │      先生が UI に到達できない場合は、Admin の「クラス・課題 →クラス（学級）検索」から
   │      運用者がクラスのアーカイブを解除できる（docs/admin/README.md。中の課題の状態は変わらない）
   └─ アーカイブ済み一覧にも無い → 【期限切れ（TTL 削除）の可能性】→ 2 へ

2. スナップショットを検索する（運用者、下記「復元スクリプト」）
   ├─ 見つかった → dry-run でプラン確認 → --apply で復元 → 3 へ
   └─ 見つからない → ARCHIVE_RETENTION_DAYS（365日）超過。復元不可能。
        その旨を丁寧に回答する（提出物のダウンロード習慣と期限アラートを案内）

3. 復元後の確認と連絡
   - 先生に「クラス一覧を再読み込みして確認してください」と連絡
   - 参加コード・席番号・提出物・（TTL が残っていれば）生徒セッションは元のまま有効
   - 復元後の保存期限は復元時点から 90 日（--ttl-days で変更可）であることを伝える
```

## 前提条件

```bash
cd infra/smalruby-classroom

# ステージを .env symlink で選択（deploy と同じ流儀。コマンドラインで env 上書きしない）
ls -la .env            # -> .env.stg または .env.prod

# AWS クレデンシャル（コンテナ内 SSO）
aws sso login --sso-session smalruby --use-device-code   # 失効時のみ
export AWS_PROFILE=smalruby
eval "$(aws configure export-credentials --profile smalruby --format env)"
```

## 復元スクリプト `bin/restore-classroom.ts`

**デフォルトは dry-run**（何も書き込まない）。プランを確認してから `--apply` を付けて実行する。

```bash
# 参加コードで検索（先生に聞くのが最速。大文字小文字は不問）
npx ts-node bin/restore-classroom.ts --join-code abc234

# クラス名（部分一致）で検索。複数一致時は候補一覧が出るので --classroom-id で特定
npx ts-node bin/restore-classroom.ts --class-name "2年1組"

# classroomId 直接指定
npx ts-node bin/restore-classroom.ts --classroom-id <uuid>

# プラン確認後、実行
npx ts-node bin/restore-classroom.ts --classroom-id <uuid> --apply
```

| フラグ | 意味 | 既定 |
|--------|------|------|
| `--classroom-id` / `--join-code` / `--class-name` | 復元対象の指定（いずれか必須） | — |
| `--apply` | 実際に書き込む | dry-run |
| `--ttl-days` | 復元データの新しい保存期限 | 90 |
| `--group-ttl-days` | 復元するクラス（学級）の保存期限 | 400 |

### スクリプトの挙動

- **対象がまだ DynamoDB に生きている場合は no-op**: 「UI から復元してください」と案内して終了（誤アーカイブは運用者の出番ではない）
- 復元内容: 課題本体（`status: active` + `restoredAt` スタンプ）+ メンバー + 提出メタ + （消えていれば）所属クラス（group）。**TTL はすべて実行時点から再設定**（過去の TTL のまま書くと即再削除されるため）
- 提出ファイル（S3 実体）の存在確認を行い、欠落があれば dry-run 時に警告表示
- 課題本体の書き込みは `attribute_not_exists` 条件付き（復元の競合で生きているデータを上書きしない）

## よくあるケース

| 状況 | 対応 |
|------|------|
| アーカイブ済み一覧に見えている | 先生自身が UI で「元に戻す」（運用者対応不要） |
| 課題は生きているがクラス（学級）をアーカイブして見つけられない | クラス一覧の「アーカイブ済みのクラス」を案内 |
| TTL 切れ・スナップショットあり | スクリプトで復元 |
| TTL 切れ・スナップショット無し（365日超過） | 復元不可。期限アラート（保存期限バッジ・バナー）と「全課題の提出物をダウンロード」機能を案内し、再発を防ぐ |
| 復元したが提出ファイルが一部欠落 | S3 lifecycle（365日）を過ぎた分は実体が無い。メタデータと残存分のみ復元される |

## 返信テンプレート

**復元できた場合:**

> ご連絡ありがとうございます。ご指定のクラス（課題）を復元しました。クラス管理画面を再読み込みしてご確認ください。参加コード・出席番号・提出物はそのままお使いいただけます。なお、復元したデータの保存期限は本日から 90 日です。期限が近づくと課題ボードに残り日数が表示されますので、「全課題の提出物をダウンロード」で保存されることをおすすめします。

**復元できない場合（保持期間超過）:**

> ご連絡ありがとうございます。恐れ入りますが、ご指定のクラスはデータの保持期間（削除から 1 年）を過ぎており、復元することができませんでした。今後は、課題ボードの保存期限表示をご確認のうえ、「全課題の提出物をダウンロード」機能でお手元に保存いただけますようお願いいたします。
