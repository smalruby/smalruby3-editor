# 日本語モードの方針（共通テスト用プログラム表記）

> **🆕 Smalruby 独自** — upstream に存在しない、Smalruby のために新規追加された機能

日本語モード（コードや docs では「DNCL モード」と呼んでいる）を変えるときは、まずこの方針を読む。
文法・記号・変換の向きで迷ったときは、ここに書いた順で決める。

## 何に対応するのか

スモウルビーの日本語モードが対応するのは、大学入学共通テスト「情報I」で使われる
**共通テスト用プログラム表記**である。

- 共通テスト用プログラム表記には、まとまった仕様書が無い。文法ははっきり決まっておらず、
  問題文の中で必要な補足をして、前提知識が無くても答えられるようにしている。
- 試験で問われるのは、穴埋めや「ある入力で出力がどうなるか」に答える力、つまり
  **問題の前提文を含めて、初めて見る書き方を読み解く力**である。0 からプログラムを書く力は
  問われない（記述式の問題は出ない）。

### DNCL は別のもの

大学入試センターの「共通テスト手順記述標準言語（DNCL）の説明」（2022 年 1 月）は、
**「情報関係基礎」**（専門学科・総合学科の受験者向け）のための言語の説明であり、情報I の
共通テスト用プログラム表記とは別のものである。

| | DNCL | 共通テスト用プログラム表記 |
|---|---|---|
| 試験 | 情報関係基礎 | 情報I（2025 年〜） |
| 仕様 | 大学入試センターが説明資料を公開 | まとまった仕様書は無い。試作問題・過去問に例があるだけ |
| 代入 | `kosu ← 3` | `kosu = 3` |
| 表示 | `kosu を表示する` | `表示する(kosu)` |
| ブロックの終わり | `を実行する` / `を繰り返す` の行 | 字下げと、行の左の罫線（`｜` / `⎿`） |
| かつ / または | `かつ` / `または` / `でない` | `and` / `or` / `not` |

- 情報I の問題で DNCL の書き方が参考にされることはあるが、**受験者が DNCL を知識として
  知っている前提の問題は出ない**。
- コードと docs で「DNCLv2」と呼んでいる形式（行番号・`｜` / `⎿`・`ならば:`・`and` / `or`）は、
  実際には共通テスト用プログラム表記の例題の書き方である。「Smalruby DNCL」は DNCL の書き方を
  もとにしている。呼び方の整理は日本語モードの方針切り替えの EPIC で行う。

## 日本語モードの目的

- 日本語モードは、**プログラムを読む力をつけるための機能**とする。書きやすさより、問題文の
  プログラムをそのまま読めること、動かして変数の変化を確かめられることを優先する。

## 文法の決め方（優先順位）

共通テスト用プログラム表記には決まった文法が無いので、次の順で決める。

1. いくつかの問題文（試作問題・過去問・教科書や問題集の例）を集めて、共通の書き方を探す。
2. ベースにする文法は **DNCL** とする。問題文の書き方に揺れがあるときは、DNCL か、
   DNCL の書き方に近いものを選ぶ。
3. DNCL に無い書き方は、複数の例題を探し、もっとも DNCL に近いもの、または Ruby の書き方に
   近いものを選ぶ。
4. 決めた理由（どの例題を見たか、ほかにどんな書き方があったか）を Issue か PR に残す。

## 設定で文法を選べるようにする（方針切り替えで目指す形）

問題によって書き方が違う（例: コメントを `#` で書くか `//` で書くか）ので、次の形を目指す。
細かいことは基本設計で決める。

- 文法を決める設定をチェックボックスで選べる。
  - 例: コメントは `#` にする、またはコメントは `//` にする。`//` をコメントにしたときは、
    `//` を整数の割り算には使えない。
- 選んだ設定は、**プログラムの冒頭に説明文として書かれる**（問題文の前提の説明と同じ役目）。
- 専門的でない受験者には細かい設定が難しいので、**よくある設定のパターンを用意**する。
- プログラムは、選んだ設定に従った文法で表される（Ruby やブロックから日本語にするときも）。

## AI と autopilot が守ること

- 日本語モードの文法・記号を足したり変えたりするときは、DNCL の説明資料だけを根拠にしない。
  共通テスト用プログラム表記の例題（試作問題・過去問）で使われているかを確かめ、上の
  「文法の決め方」に従う。
- 「DNCL」と書いてあっても、情報関係基礎の DNCL のことか、情報I の共通テスト用プログラム表記の
  ことかを区別して書く。
- 大学入試センターの試験問題の著作権はセンターにあり、二次利用（複写して配る、問題の一部や全部を
  使った問題集を作る。インターネット上も含む）にはセンターへの利用申請が要る。予備校などのサイトに
  載っている問題も、問題そのものの権利はセンターにあると考える。
  - Issue・PR・docs では、記法を示すのに要る数行だけを、出典（発行者・URL・年度・問題番号）を
    付けて引用する。問題文の全文や図の全体は載せない。
  - 実際の問題を、そのままテストのデータや教材としてリポジトリやスモウルビーに入れない。テストや
    教材には、記法をまねて自分で作ったプログラムを使う。
  - 実際の問題を教材に使いたいときは、人間がセンターへの利用申請を判断する。
