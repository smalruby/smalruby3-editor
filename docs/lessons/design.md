# レッスンの設計方針

> **🆕 Smalruby 独自** — upstream に存在しない、Smalruby のために新規追加された機能

レッスン（コース › レッスン › チャレンジ）で**決めたこと**と、**そう決めた理由**をまとめる。
コースやチャレンジを足すとき、画面を直すときは、まずここに沿っているかを確かめる。方針を変えるときは、
先にこのファイルを直してから実装する（実装の詳細・データの形・data-testid は [`README.md`](README.md)）。

## 目的

- 先生の説明がなくても、順番にやればスモウルビーでのプログラミングのやり方が身につくこと。
- 探すための一覧ではなく、「何をやって、どこまでできたか」が見えること。
- 設計の出発点: 中学 2 年のチャットアプリの授業で、スプライトを足す・押したら反応する、といった基本が
  できなかった。先生なしで基本を一通り身につける入口が要る。

## 使われる場面（前提）

- **授業のパソコンは 1300×600**。レッスン表・課題バー・ヒントは、この大きさでスクロールせずに使えること。
  対象はステージが**小・中サイズ**のとき（中が既定）。**大サイズは対象外**。1300×600 で大きいステージを選ぶと、ステージの下のスプライトの
  領域が画面の外に出るが、それは選んだ生徒側で（ブラウザ全体のズームを変えるなどして）対応する前提とし、
  スモウルビーでは何もしない。
- **先生がプロジェクターに映して説明する**。課題の全文は大きめの字で、画面に出したままにできること。
- **共用のパソコン**が多い。記録は端末に残し、段 2 でクラスの課題に引き継ぐ。
- SP（スマホの縦・横）でも使える。ただし主な対象は授業のパソコン。
- 小学 3 年生以下は主な対象にしない。文言は漢字まじりの普通の日本語（ひらがなだけの表示は `ja-Hira`）。

## 階層と名前

| 階層 | 画面での表し方 | 決まり |
|---|---|---|
| 言語 | レッスン表の上の帯のボタン | ブロック／Ruby／日本語（DNCL）。**コースがある言語のボタンだけ出す**（いまは「ブロック」だけ） |
| コース | 大きい見出し | 全部できたら名前の前に ✓。右にプログレスバーと「n / 全部」 |
| レッスン | コースの中の小さい見出し | 「レッスン 1」＋ 名前。1 つのレッスンは 3〜4 個のチャレンジ |
| チャレンジ | カード | 1 つ 5 分・3〜5 ブロックで作れる大きさ。チャレンジの ID は一度出したら変えない（記録のキー） |

- 最初のコースはブロック › 「きょうからプログラマー」（はじめての人が全員やる）。
  レッスン 1「うごかしてみよう」（1〜4）、レッスン 2「えらんで たずねよう」（5〜7）、
  レッスン 3「おぼえて つたえよう」（8〜11）。分け方は「覚えること」のまとまり
  （きっかけと動き・見た目・音／条件と入力／変数・メッセージ・リスト）。
- レッスンを分け直しても、チャレンジの ID と記録は変えない。記録はチャレンジ ID を主にし、
  どのレッスンに属するかは、いまの定義から読みかえる。

## 段 1 で入れないもの（入れないと決めたもの）

| 入れないもの | 理由・代わり |
|---|---|
| **「必須」** | レッスン単体では必須の理由を生徒に説明できない。**クラスの課題とレッスンを紐付けて、先生が必須にしたときだけ**必須のふるまいをする（段 2）。バーを分けるかは[段 2](#段-2-クラスの課題とレッスン)の未定 |
| **「できること」の一覧** | メンテナンスし続けるのが難しい。バッジなどのゲーミフィケーションを考えるときにあらためて作る |
| **「クリア！」「プログラマー デビュー！」などの言葉** | コースごとに言葉を決めるのが難しい。コース名の前の ✓ だけにする |
| **「レッスンをはじめよう！」などの誘う吹き出し** | どの端末にも出さない。レッスンに入る道は、メニューの「レッスン」と、段 2 の「課題にレッスンを紐付けたときだけ、クラスに参加して『はじめる』を選ぶとそのコースを開く」 |
| **カードの絵（イラスト・スクリーンショット）** | 描き続けるのが難しい。名前と単色だけにする（下の「カード」） |
| **スクリーンショットを使ったヒント** | 古くなる。ヒントの吹き出しには本物のブロックを描く |

## レッスン表

- **見た目はスモウルビーの「スプライトを選ぶ」画面と、Scratch の「チュートリアルを選ぶ」画面に近づける**。
  児童・生徒は見慣れていて、いまどれが選ばれているか（オレンジのボタン）、あとから Ruby などが押せる
  ようになることが伝わる。
  - 紫のヘッダー（← 戻る ／ 「レッスンを選ぶ」）。その下の薄い紫の帯に、検索 ＋ 区切り ＋ 言語のボタン。
  - その下に、コースの見出し → レッスンの見出し → チャレンジのカード。
- **1300×600 で、いまのコース（3 レッスン 11 枚）がスクロールせずに見える**こと。カードを足す・大きく
  するときはこれを確かめる。
- **検索**: チャレンジの名前の部分一致。合うものが無いレッスン・コースは隠す。大文字小文字・全角半角・
  カタカナとひらがなは区別しない。
- **増えたとき**: 1 ページに縦に並べる（コースが少ないあいだは、いちばん見わたしやすい）。コースが 4 つを
  超えたら、帯の 2 段目にコースのボタン（押すとそのコースまでスクロール）を出す。さらに増えたら
  「コースのカード → コースのページ」の 2 段階の入口を足す（いまのページがそのままコースのページになる）。
- SP: 帯は 1 行に収め、はみ出すボタンは横にスクロール。カードは縦で 2 列。

### カード

- **形: 左にブロックの色の帯、右に名前（横長）**。背が低く、カードが増えても場所を取らない。
- **色: そのチャレンジで多く使うブロックの色**。数え方:
  - 「プログラムを入れる」で入る、できあがりのプログラム（ほかのスプライトの分も）を、ブロックにして数える。
  - 形のあるブロックはすべて数える（帽子のブロック・値のブロックを含む。数の入力などの白い穴は数えない）。
  - **同じ数で並んだら、そのチャレンジで覚えるメインのブロックの色**にする。
  - 色はブロックのなかまの色そのまま。拡張機能は拡張の緑。
  - 例: 「キーで音を鳴らそう」はサウンド 2・イベント 1 → サウンド。「矢印キーで動かそう」は動き 2・イベント 2 で
    同数 → メインの動き。
- できたら ✓。「次のチャレンジ」で開いたときは、次にやるカードに「次はこれ！」。

## チャレンジ

- **毎回、新しい作品から始める**（前のチャレンジの続きにしない）。
- パレットは使うブロックだけ（`allowedBlocks`）。ブロックの初期値は、仕様の表記（`[1 ▼]`・`(3)`）に合わせる。
  子どもが作る名前（変数・リスト・メッセージ）の ▼ には初期値を入れない。
- 英語の UI では、子どもが作る名前も英語にする（`count` / `talk` / `hello` など）。判定はどの言語の名前でも通す。
- **「できた」の判定はプログラムの形を見ない**。`uses`（決めたブロックが動いた）と `result`（変数・リスト・
  言った文字などの結果）だけ。答えのプログラムを入れて動かしても「できた」にする（区別しない）。

## 課題バー

- 上に課題の 1 行と「何個め / そのレッスンの全部」（レッスンの中の番号）。
- **画面の幅いっぱい**（エディタの列だけでなく、ステージの列の上もおおう）。「ヒント」「ほかのチャレンジへ」は
  **画面の右端**に置く。ステージの列（旗・止める・ステージの大きさ）は帯の下に下がり、そのまま押せる。
  縦が 40px 減る分は、中サイズのステージのスプライトの情報を詰め（`docs/sprite/README.md`）、右下のステージの列の
  見出し「ステージ」を出さないで補う（`docs/stage/README.md`）。ステージの列の見出しを消してもステージ（canvas）の
  位置は変わらないので、下の resize の決まりには当たらない。
- **ステージの列を（大きさを変えずに）上下左右に動かす変更は、動かしたあと window に `resize` を送る**。
  ステージは canvas の位置を resize / scroll のときにしか測り直さず、送らないとマウスの座標がずれて
  「マウスのポインターに触れた」が真にならない。課題バーが出る・消えるときは `containers/lesson-mode.jsx` が
  送っている。段 2 でバーを 2 本にするなど、レッスンの途中でバーの高さが変わるときも同じく送る。
- **全文はマウスを乗せたら下に出す**（課題が長くても短くても。改行もそのまま。小さな画像も出せる）。
  「全文」ボタンは置かない。SP では課題の文のタップで開き、もう一度で閉じる。
  - ヒントの吹き出しが出ていても、乗せれば全文を上に重ねて出す。メニューバーのメニューが開いているときと、
    「できた！」が出ているときは出さない。
- 課題の文は、読みやすい位置で改行しておく（定義の改行をそのまま出す）。
- 「やめる」とは書かない。前向きな言葉（「ほかのチャレンジへ」）にして、押すとレッスン表を開く。
- **右端に「レッスンをおえる」**（「ほかのチャレンジへ」の右）。「ほかのチャレンジへ」より目立たせない
  （透明地に白い枠）。押すとレッスンから出て、いまのプログラムを残したまま、ブロックを全部使えるいつもの画面に
  もどる（レッスン表は開かない・確認は出さない）。レッスンにもどるのはメニューの「レッスン」から。
  「できた！」の表示には入れない。

## ヒント

- 吹き出しの中に**本物のブロック**を描く。スポットライト（周りを暗くする）は、はじめて開いたチャレンジの
  基本操作だけ。
- **帽子のブロックを置く手順を抜かさない**。できあがりのプログラムにある帽子のブロック（「〜キーが
  押されたとき」「旗が押されたとき」「このスプライトが押されたとき」「〜を受け取ったとき」など）は、どれも
  どこかのヒントで置き方を示す。「〜の下に〜をつなげよう」と言う前に、その上のブロックを置くページがあること。
  「〜したら〜するプログラムを作ろう」のように 1 ページでまとめるときは、絵に帽子のブロックから描く。
- **絵は、そのページで置いてほしいブロックを、置いてほしい並びのまま描く**。文言で「〜と〜を入れよう」
  「2 組」「上と下に」と言うなら、その全部を、組み立てたときの並び（つながり・入れ子）で描く。一部だけを
  描くと、何をいくつ置くかが伝わらない（例: 「繰り返す」の中の「背景を Canyon にする・1 秒待つ・背景を
  Arctic にする・1 秒待つ」）。絵の無いページ（タブ・ステージ・キーを指すもの）はこの限りでない。
- **つなげる相手・置く位置を言うページは、相手のブロックもいっしょに描く**。「〜の下につなげよう」「〜の上に
  入れよう」「〜の中に入れよう」「穴に入れよう」なら、置くブロックだけでなく、相手（すぐ上のブロック・入れる先の
  ブロック）とつないだ並びで描く（例: 「ずっと」だけでなく「旗が押されたとき＋ずっと」、「タイマーをリセット」だけで
  なく「タイマーをリセット＋聞いて待つ」）。描くのは相手と置くブロックまでで、スクリプト全体にはしない
  （吹き出しが大きくなりすぎないように）。
- **「できた」になる操作を促すヒントを、手順の最後（「うまく動かないときは」のページの前）にする**（キーを押す・ステージのスプライトを押す・旗を押す・
  答えを入れるなど、課題を試すページ）。できたら吹き出しが閉じるので、そのあとのヒントは見られない。
  ブロックの消し方のような「知っておくとよいこと」も、試すページより前に置く。試すページは、ステージ・
  キーボード・旗を指す。
- **チャレンジを始めたら、ヒントの 1 ページ目を自動で開く**（ヒントボタンに気づかない子のため）。
- **ドラッグで動かせる**（じゃまなとき）。画面の外には出さない。
- 最後のページ（うまく動かないときは）:
  - 「プログラムを入れる」とは書かない。**「正解のプログラムを確認する」**にして、押すと
    「正解のプログラムで置き換えますか？あなたが作成したプログラムは消えます」［いいえ］［はい］を出す。
  - 進めるボタンは「おわり」。押すと閉じて、次に開くときは 1 ページ目から。
- **できたら吹き出しを閉じる**（「できた！」と「次のチャレンジ」を見てほしいため）。

## 「できた！」のあと

- 生徒に「次に何をすればよいか」がわかるようにする。字は大きく、出ている理由がひと目でわかるようにする。
- **チャレンジの名前は出さない**（課題バーに出ている）。「クリア！」などのことばは使わない。
- **チャレンジの終わりとレッスンの終わりを見分けられるようにする**。3 つの場面:
  1. **チャレンジができた（レッスンの途中）**: 大きく「できた！」。その下に、レッスンの中のできた数を丸で
     （できた = 塗り、いまできたもの = 塗り＋強調）と「このレッスンは、あと n つ」。ボタンは「次のチャレンジへ」
     （レッスン表のいまのレッスンを開き、次にやるチャレンジに「次はこれ！」）。色は青。
  2. **レッスンのチャレンジが全部できた（まだ全部できていないレッスンがある）**: 「できた！」と同じ大きさで
     「レッスン n ぜんぶできた！」、丸は全部塗り、2 行目「「レッスン名」の n つ、全部できました」。
     ボタンは「次のレッスンへ」（まだ全部できていない次のレッスンをレッスン表で開く）。**枠とボタンはお祝いの
     オレンジ**、アイコンは 🏆。
  3. **レッスンが全部できて、ほかに残っているレッスンが無い**: 2 と同じ形で、2 行目「「コース名」のレッスンは、
     これで全部です」、ボタンは「レッスン表へ」。後ろのレッスンは全部できていても前のレッスンを飛ばしているときは、
     「これで全部です」とは言わず 2 行目をレッスン名の行にする（ボタンは「レッスン表へ」のまま。飛ばしたレッスンは
     レッスン表で選ぶ）。
- × は置かない。2 つめのボタン「もう少し見る」（白地に枠）で閉じるだけ。次へ進むときは課題バーの
  「ほかのチャレンジへ」。

## 段 2 以降への申し送り

- **入口・必須・記録の引き継ぎ**: 下の「段 2: クラスの課題とレッスン」で決めた。
- **Ruby・日本語のコース**: コースができたら言語のボタンを出す。レッスン表の形は同じ。
- **「できること」の一覧・バッジ**: ゲーミフィケーションを考えるときに、あらためて設計する（段 2 でも扱わない）。

## 段 2: クラスの課題とレッスン

先生がクラスの課題にレッスンを紐付け、**必須**と**完了の条件**を決め、生徒の**進み具合**を見られるようにする。
授業で先生が、だれがどこで止まっているかを見て声をかけられるようにするため。これまでの「提出した／していない」の
2 択に、「どのチャレンジまで進んだか」が加わる。

ここにはレッスンの側の決まりを書く。先生の画面（説明タブ・座席・「進み具合」タブ・パネル）、生徒のクラスの画面、
CSV と採点は [`docs/classroom/ui-ux.md`](../classroom/ui-ux.md) の「レッスンの課題」に書く。

> 「（推奨で決めた）」と書いたものは、設計の相談で決まっていない細かいところを、推奨の案で決めたもの。
> develop へのマージの前に人間と確かめる。「未定」は、書いてある sub-issue で決める。

### 課題とレッスン

- **新しい課題の種類は作らない**。いまの課題に「レッスン」欄を足す。レッスンを選ばなければ、いままでの課題のまま。
- 1 つの課題に**コースは 1 つ**。レッスンにチェックすると中のチャレンジが全部入り、チャレンジごとに外せる。
  対象のレッスンは複数選べる。
- チャレンジの順番は**レッスンの順のまま**（先生は並べかえない）。
- 「**作品の提出もする**」を ON / OFF できる。ON のとき、提出は**課題につき最後の 1 回**。レッスンごとには求めない。

### 入口

- レッスンに入る道は 2 つだけ。**メニューの「レッスン」**と、**レッスンを紐付けた課題に参加して「はじめる」**。
  「レッスンをはじめよう！」の吹き出しは出さない（段 1 と同じ）。
- **「はじめる」**: レッスン表を課題のコースで開き、**課題のチャレンジだけ**を出す。課題の外のチャレンジは出さない。
  先生がチェックを外すのは「情報量を減らしたい」という意思表示なので、それに従う。
- **課題に参加したまま、メニューの「レッスン」から開いたとき**: コース全体を出し、上に**課題の帯**を載せる。
  課題の外のチャレンジもできる（記録は端末に残るが、クラスには送らない）。
- 参加完了の画面で、この課題がレッスンの課題であることと、作品も提出するかを先に伝える
  （生徒の「提出ボタンがありません」という質問を減らすため。文言は ui-ux.md）。
- レッスンの課題の「はじめる」は、いつもレッスン表を開く。スターターの無いレッスンの課題では、「どこから始めますか？」
  （スターター・前回の提出物）は出さない。スターターもある課題だけ、いままでの選択肢を「はじめる」と並べて出す
  （チャレンジは毎回新しい作品から始まるので、スターターや前回の提出物は、課題クリアのあとの作品づくりにだけ使う）（推奨で決めた）。
- 課題のチャレンジを開いたときだけ「課題から開いた」とする（GA の計測・クラスへ送る分）。課題のチャレンジから
  「ほかのチャレンジへ」「次のチャレンジへ」を押したときは、レッスン表をまた課題のチャレンジだけで開き、
  次にやる課題のチャレンジに「次はこれ！」を付ける（推奨で決めた）。

### 必須

- **レッスン単体では**（クラスの課題と紐付けないとき）、必須マークも必須のふるまいも出さない（段 1 と同じ）。
- **先生が課題で ★ を付けたチャレンジだけ**が必須になる。★ は選んだチャレンジにだけ付けられる。0 個でもよい。
- レッスン表のカードでは、★ はカードの**右**に出す。
- 必須が終わっていないことは、先生の表で別に見える。採点では減点しない（できた分の合計のまま・ui-ux.md の「採点」）。
- 段 1 で申し送った「必須があるときだけ、コースのバーを『必須』と『そのほか』の 2 本に分ける」は、課題の帯では
  **分けない**。バーは 1 本のまま、必須のチャレンジの丸に ★ を付け、「★ あと n」を並べる（推奨で決めた）。

### 完了の条件

- 課題ごとに「**全部**」か「**n つ（必須をふくむ）**」を選ぶ。既定は「全部」。
- 「n つ」の n は、必須の数から選んだチャレンジの数までにする（必須より少ない数は選べない）（推奨で決めた）。
- **「前からできた」（課題の前から端末にできた記録があったもの）も、条件の数に入れる**。課題ごとに入れる／入れないを
  切りかえる設定は作らない。やっていればその分お得、という考え方。
- 条件を満たすことを「**課題クリア**」と呼ぶ。課題は先生が決めた区切りなので、段 1 で使わなかった「クリア」を
  ここでは使う。

### 課題の帯

- レッスン表の上に、課題の帯を出す。中身は**課題名・条件・丸（チャレンジごと。★ は必須）・あと n つ**。
- 丸は、できた = 塗り、まだ = 白。「前」も塗る（推奨で決めた）。
- 課題クリアのあと、作品も提出する課題では、帯に提出の案内（下）と［課題を提出する］を出す。
- チャレンジの中（課題バー）では、課題のチャレンジのときだけ、課題バーの**同じ行**に小さな帯（丸と「あと n つで
  課題クリア」・課題クリアのあとは「✓ 課題クリア」）を出す。行を足さず、バーの高さは変えない（そのため `resize` の
  決まりには当たらない）（推奨で決めた）。
- 課題の帯の数え方（あと n つ・できた数・課題クリア・メニューバーの印）は
  `packages/scratch-gui/src/lib/lessons/assignment-progress.js` の純粋関数にまとめる。先生の画面（座席の色・
  「進み具合」タブ）も同じ関数で数える。

### 課題クリア

- 条件を満たしたチャレンジの「できた！」は、**「課題クリア！」**にする。段 1 の「レッスン n ぜんぶできた！」より優先する。
- 形は段 1 の 2・3 と同じお祝いの形（オレンジの枠とボタン・🏆）にそろえる（推奨で決めた）。
- **作品も提出する課題**: 「課題クリア！」の下に「**レッスンで学んだことをつかって、自由にプログラムをつくろう。
  できたら作品を提出しよう**」と出し、主ボタンを「**課題を提出する**」にする。同じ案内は、クラスの画面と
  レッスン表の課題の帯にも出す。案内を出すのは**完了の条件を満たしたとき**から。
- 作品を提出しない課題: 主ボタンは段 1 と同じ（次のレッスンへ／レッスン表へ）（推奨で決めた）。
- 課題クリアのあとにできたチャレンジは、ふつうの「できた！」に戻す（課題クリア！は 1 回だけ）（推奨で決めた）。

### 本人の確認

共用のパソコンでは、端末に残っている記録が前に使った人のものかもしれない。そのまま送ると、先生の表に
ほかの人の記録が出る。

- **その課題ではじめて送るとき**、課題の対象のチャレンジの記録が端末にあれば、**一度だけ**
  「**あなたがやった記録ですか？**」と聞く。課題の前の記録が無ければ聞かない。
- 「**わたしの記録です**」→ 送る。先生の表では「前」（課題の前からできていた）として見える。
- 「**ちがう**」→ すぐには消さず、**もう一度確かめる**（判断できない生徒が多いため）。文言で決め方を伝える:
  「**自分のパソコンなら**消さずに戻って『わたしの記録です』を選ぼう。**みんなで使うパソコンなら**消そう」。
  - ［戻る］→ 1 つめの確認に戻る。［消す］→ 送らずに、**端末のレッスンの記録を空にする**（ボタンの名前は推奨で決めた）。
- 答えはその課題について端末に覚え、同じ課題では二度と聞かない（推奨で決めた）。
- 「前」にするのは、はじめて送るときに端末にあった記録（推奨で決めた）。課題に参加したあとにできたものは「前」にしない。

### 進み具合の送り方

送る量と回数をおさえて、費用を小さくする（1 クラス 40 人 × 11 チャレンジ × 2 回（開いた・できた）≒ 授業 1 回で 880 回の書き込みまで）。

- クラスへ送るのは「**できた**」と「**チャレンジを開いた**」だけ。「正解のプログラムを確認した」はクラスには送らない。
- 送るのは、**できたとき・課題のチャレンジを開いたとき・クラスの画面を開いたとき**（まとめて）。
  **定期的な問い合わせはしない**。
- **1 回の送信は「席 × 課題」の 1 件にまとめる**（その席・その課題の進み具合をまとめて上書きする）。
  チャレンジごとに別々に送らない。
- 送るのは課題のチャレンジだけ。課題の外のチャレンジは送らない（サーバーでも捨てる）。できた時刻は過去に戻さない
  （一度できたものは消えない）。
- 端末の記録は、クラスに関係ない形（チャレンジ ID・できた日時）のまま残す。クラスへ送る分は、そこから作る。
- 送れなかったとき（通信が切れていたなど）は、次に送るときにまとめて送る（推奨で決めた。細かいところは #1600）。

### GA の計測の方針

クラスの進み具合とは別に、**レッスン全体**（課題の外もふくむ・クラスに参加していないときもふくむ）の使われ方を
GA で計測する。目的は、**人気のないコンテンツ**と**滞在の長いヒント**を見つけて見直すこと。

- 計測するもの: チャレンジを開いた・できた・ヒントのページ（何ページめか）と滞在時間・正解のプログラムを確認した・
  レッスンをおえる など。
- **ヒントの滞在時間**は、ページごとに、**そのページを開いてから、次のページへ進む・閉じる・「できた！」になる
  まで**の時間。
- **個人を特定する ID は送らない**。席番号・ニックネーム・セッションも送らない。課題や参加コードの ID も送らない
  （推奨で決めた）。送るのはコース・レッスン・チャレンジの ID とページの番号くらいにする。
- イベントの名前と項目は [`README.md`](README.md) の「GA の計測」。
