# 日本語モード（DNCL モード）の方針

`packages/scratch-gui/src/lib/dncl/`、`src/containers/ruby-tab/dncl-*.js`、`src/lib/genai-dncl-prompt.js`、
`docs/dncl/`、`docs/smalruby-dncl-spec.ja.md` を変えるときは、**先に `docs/dncl/policy.md` を読む**。

要点（正準は `docs/dncl/policy.md`）:

- 対応するのは、共通テスト「情報I」の**共通テスト用プログラム表記**。まとまった仕様書は無く、
  問題文の補足で読めるようにした書き方。試験で問われるのは読み解く力で、0 から書く力ではない。
- 大学入試センターの「DNCL の説明」は**情報関係基礎**のためのもので、情報I とは別物。
  受験者が DNCL を知っている前提の問題は出ない。
- 呼び方: 共通テスト用プログラム表記に合わせた書き方は**標準の形**（旧「DNCLv2」。今後はこう呼ばない）。
  `を実行する` / `を繰り返す` で閉じ、`かつ` / `または` を使ういまの書き方は**DNCL 風の形**（旧「Smalruby DNCL」）。
- 日本語モードは**プログラムを読む力をつけるための機能**。支える読み方は、公式に多い問われ方の順に、
  ①行番号と罫線を残したまま読めて動かせる、②行番号で行を指せる、③トレース、④実行回数、⑤空欄・行の差し込みを試せる。
- 「例題」は**公式の資料だけ**（例示・サンプル・試作・本試験・追試験）。非公式は、公式に無い記法の候補探しと、
  受け付ける揺れを知るためにだけ使う。意味が同じ揺れは**新しい年度の本試験・追試験**に合わせる。
  例示は、問題文に約束が無いときの既定の解釈として使う。
- 文法の決め方: ①例題から標準的な文法を見出す → ②例題に無いものは DNCL（**言葉は DNCL、見た目は例題**。
  例: `関数 名前(引数):` と罫線。`と定義する` の行は置かない）→ ③揺れが新しい年度でも決まらず DNCL に
  記載があれば DNCL → ④DNCL にも無ければ、例題の中から DNCL か Ruby に近いもの → ⑤例題にも DNCL にも
  無いもの（戻り値・要素の追加など）は、非公式の多数派か Ruby に近いもの → ⑥理由を Issue / PR に残す。
- 設定にするのは、**意味が変わるもの、または問題文で約束されるもの**（添字の始まり、コメントの記号など）。
  見た目だけの揺れ（行番号の形、罫線の文字、全角・半角、引き算の記号）は設定にせず、
  読むときは全部受け付けて、書くときは 1 つにそろえる。よくある設定のパターンを用意する。
- 冒頭の説明文は、**公式の問題文の約束の型**に合わせる（常体・「，」）。問題の中で説明されない約束（罫線・`表示する`）は書かない。
- 移り方: 表示と書き出しは標準の形へ切り替え、DNCL 風の形も読み込みは続ける。細部は基本設計で決める。
- テスト・教材にセンターの問題を使わない（記法をまねた自作のプログラムを使う）。引用は数行と出典だけ。
